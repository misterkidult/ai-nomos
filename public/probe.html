2026-09-01 複測結論（Chrome 152 原生，旗標已開）
  • ① document.modelContext 存在、registerTool 成功、getTools() 正常回工具 —— 通
  • ③ 那些工具沒有進 Claude in Chrome 的工具清單 —— 仍斷（同 8/27）。 agent 只能用 javascript_tool 手動 executeTool 繞過橋接，那不算 agent 呼叫
  • requestUserInteraction：Chrome 152 原生 client 不提供。 ai-nomos 不受影響 —— 契約 §6 的第四關本來就是頁面自己畫確認框，不靠 client

Chrome 152 原生 executeTool 的兩個坑（自測按鈕已避開，手動呼叫要注意）：

  • 第一個參數要傳 getTools() 回來的 tool 物件，傳字串 'ping' 會丟 not of type 'RegisteredTool'
  • 第二個參數要字串化的 JSON，傳 {} 物件會丟 Failed to parse input arguments
2026-09-01 追查：③ 為什麼斷 —— 拆擴充包看到的答案

不再靠試誤猜。直接讀 Claude in Chrome 擴充的 bundle（fcoeoabgfenejglbffodgkkbkcdhcgfn v1.0.90）， 用字串搜尋確認它到底有沒有讀頁面註冊的工具。

  • 整包 0 次命中：modelContext、webmcp、registerTool、 getTools、provideContext 全都是 0。 這個版本根本沒寫讀 WebMCP 的程式碼 —— 不是權限沒開、不是旗標沒設，是功能不存在
  • mcp 有 190 次命中，但方向相反：那是 tabs_context_mcp／tabs_create_mcp／tabs_close_mcp， 擴充自己當 MCP server、把分頁開給外部 client 用。 WebMCP 要的是「擴充當 client、讀頁面提供的工具」，兩者是反過來的
  • 唯一真的能把外部工具餵進工具清單的路徑是 remote MCP server （工具名長成 mcp__<uuid>__<tool>，走 OAuth，UI 叫 Connectors）。 但這個 build 的 Connectors 選單傳的是 showConnectors:!1 —— 寫死關閉

結論：Chrome 152 ＋ 擴充 1.0.90 這個組合， 「讓 Chrome 的 agent 叫得到頁面 WebMCP 工具」沒有可行路徑。 旗標 enable-webmcp-testing 只讓網頁拿得到 document.modelContext（① 通）， 它管不到擴充讀不讀（③ 斷）。這兩件事是分開的兩套程式碼。

所以不要再花時間在：換 profile、重開旗標、調權限、重裝擴充、升 Canary —— 這些都不改變「bundle 裡沒有那段程式碼」。 要等的是擴充改版。複測方法：解壓新版擴充， grep -ro "modelContext" . 不是 0 才值得重測 ③。

今天實際可用的 agent 路徑仍是 ChatGPT 桌面版（document.modelContext，Settings › Browser › Permissions 開 site tools）。
